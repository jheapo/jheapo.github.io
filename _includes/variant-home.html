The bill is visible. The cause takes investigation.

You need larger instances, and CPU use doesn’t explain why.

Memory often decides the size of the instance you pay for. If the application needs less memory, a smaller instance or a different deployment becomes possible. The first question is what can change inside the application.

Performance work keeps returning to the same service.

GC activity, allocation pressure and a growing live set take engineering time long before they cause an outage. Knowing which behaviour is responsible tells your team which work to do.

You have a heap dump, and the investigation has stalled.

A large dump, millions of objects and several plausible explanations can leave a capable team without a next step. JHeapo traces the objects, references and structures behind the symptom.
